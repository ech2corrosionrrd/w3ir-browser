# Журнал змін

Версії 1.0.0–1.20.0 розроблені й випущені 2026-10-16, 1.21.0–1.29.0 — 2026-10-17. Формат: нові можливості, зміни, виправлення.

## Не випущено
- **Бета-канал оновлень.** Налаштування → «Оновлення браузера» → «Отримувати бета-версії» (типово вимкнено): клієнт бачить пре-релізи GitHub (теги `vX.Y.Z-beta.N`). Перевірка підпису випускача та заборона зниження версії лишаються. Версія із суфіксом `-beta.N` публікується скриптом як пре-реліз, а `npm run winget:submit` для неї відмовляє.

## 1.40.0
- **Перемикач «Приховувати банери cookie».** У Налаштуваннях → Приватність окремо вмикаються списки «annoyances» блокувальника; рушій підміняється одразу, без перезапуску, а кеш для варіанта без цих списків зберігається окремо (`adblock-engine-base.bin`). ## 1.39.0
- **Інтеграція екосистеми безпеки GitHub & Threat Intelligence.** Інтегровано перевірку витоків паролів Have I Been Pwned (HIBP) за протоколом k-Anonymity (SHA-1 префікси без розкриття паролів назовні), розпізнавання відомих адрес витрачальників (Spender Labels) за базою Revoke.cash / whois під час підписів та авторизацій, а також захисний фід підозрілих доменів Polkadot-js/phishing проти крипто-шахрайств і фішингу.
- **Постійне Web3-сховище Arweave: маніфести ANS-105 та конструктор NFT.** Власна підтримка резолву маніфестів шляхів `application/x.arweave-manifest+json` у протоколі `ar://` для завантаження permaweb-сайтів і децентралізованих додатків із кешуванням і CSP. У гаманець додано інтерактивний конструктор метаданих NFT (ERC-721 / Metaplex) з прив'язкою виключно до Arweave та автовизначенням найшвидших шлюзів (Gateway Probing).
- **Безпека гаманця та верифікація смарт-контрактів.** Індикатор «Перша взаємодія» попереджає користувача під час відправлення коштів на невідомі адреси, відсутні в контактах та історії. Впроваджено автоматичну перевірку верифікації смарт-контрактів через Sourcify API v2 (`exact_match`, `match`, `unverified`).
- **Експорт історії Solana та локальний ШІ для читання.** Додано захищений від CSV-ін'єкцій експорт історії транзакцій Solana з підстановкою контактів. У режимі читання `w3ir://reader` додано локальний ШІ-переклад і конспект статті (TL;DR) через Ollama без передачі тексту на сторонні сервери.

## 1.38.0
- **Тема «Pure Obsidian» для внутрішніх сторінок.** Модернізовано інтерфейси `w3ir://settings`, `w3ir://passwords`, `w3ir://downloads`, `w3ir://history`, `w3ir://bookmarks` та `w3ir://newtab`: глибока темна графітова палітра з неоновими акцентами, сегментовані вкладки налаштувань (`.wtabs`), живий пошуковий фільтр `.wfilter-input`, аватари сайтів `.pw-avatar` / `.item-avatar`, бейджі типів файлів для завантажень, аудит паролів `.pw-audit` та інформер постійного Arweave/Irys Web3-сховища.
- **Вбудована двофакторна автентифікація (2FA / TOTP, RFC 6238).** До менеджера паролів і сховища Vault додано підтримку ключів 2FA без сторонніх бібліотек: авторозпізнавання посилань `otpauth://` і Base32-ключів, розрахунок 6-значних одноразових кодів із живим таймером зворотного відліку секундоміра на сторінці `w3ir://passwords` та копіювання коду в буфер з автоочищенням через 20 секунд. Секрети шифруються за алгоритмом AES-256-GCM разом із паролями.
- **Захист від цифрових відбитків (Anti-Fingerprinting).** Нормалізація характеристик для запобігання міжсайтовому стеженню: округлення `screen.width`/`screen.height` до найближчих 100 px (screen letterboxing), маскування ядер процесора (`hardwareConcurrency: 4`) і пам'яті (`deviceMemory: 8`), ін'єкція мікрошуму в Canvas (Canvas Noise Injection) для унеможливлення зняття унікальних GPU-хешів через `getImageData` / `toDataURL`. Перемикач у «Приватність», автоматичне включення в режимі «Максимальний захист».
- **Надійність релізів, покриття та англомовна документація.** Додано підтвердження походження збірок (Build Attestations через `actions/attest-build-provenance` у GitHub Actions), таблицю контрольних сум SHA-256 у нотатках кожного випуску, підтримку V8 Code Coverage (`npm run test:coverage`), основний англомовний `README.md` (українська версія — у `docs/README-uk.md`), 91 unit-тест без Electron і 100% синхронізацію 5 мовних каталогів.

## 1.37.0
- **Переглядач документів: CSV/TSV, JSON, текст і код.** До Markdown у `w3ir://doc` додано: **CSV/TSV** (розбір за RFC 4180 з лапками й переносами в полях, автовизначення `,` `;` табуляції `|`, таблиця з фільтром, сортуванням за заголовком, числовим порівнянням, до 5000 рядків), **JSON** (дерево зі згортанням, ледаче створення вузлів, перемикач «Текст» з форматуванням, повідомлення про помилку для некоректного файлу) та **текст/код** (`.log`, `.ini`, `.cfg`, `.conf`, `.toml`, `.yml`, `.env`, `.sql`, `.css`, `.py`, `.ts`, `.rs`, `.go`, `.java`, `.c`, `.cpp`, `.cs`, `.rb`, `.php`, `.sh`, `.diff` — номери рядків, перенос, до 20000 рядків). Виконувані й небезпечні типи (`.js`, `.ps1`, `.bat`, HTML, SVG) у переглядач не входять. З «Завантажень» у вкладці відкриваються `.md`, `.csv`, `.json`. Усе виводиться через `textContent`, нових залежностей немає (`pages/csv.js`). Друк і «У PDF» працюють для всіх типів (таблиця без елементів керування, без обрізання). Тести: `test/unit/docview.test.js`, перевірки в `auditTests`.

## 1.34.0
- **Гаманець: приховати.** Новий режим «Приховати гаманець» (Налаштування → «Гаманець» і сторінка гаманця → «Безпека»): гаманець зникає з меню, палітри команд, стартової сторінки й панелі, сайти його не бачать (провайдер вимикається, підключення відправляють порожній список рахунків), сторінка гаманця показує лише кнопку «Показати». Дані лишаються у зашифрованому сховищі; показати знову можна лише з майстер-паролем (заблоковане сховище розблоковується тим самим паролем). Поки гаманець прихований, усі його команди відхиляються. Повне видалення, як і раніше, в «Безпека» → «Видалити гаманець».
- **Гаманець: вікно підтвердження транзакції з'являється значно швидше.** Усе потрібне (nonce, оцінка газу, комісії, перевірка делегування EIP-7702, дані токена, симуляція, ціна) запитується одночасно, а не по черзі; `decimals`/`symbol`/`name` токена теж читаються паралельно. У вимірі з мок-RPC (150 мс на запит) шлях від запиту сайту до вікна скоротився з ≈1391 мс до ≈190 мс. Якщо підготовка триває понад 0,5 с, показується «Готуємо підтвердження…».
- **Гаманець: запас газу.** Для викликів контрактів ліміт газу береться з оцінки +20 % (простий переказ 21000 і значення, задані сайтом, не змінюються): нестача газу між оцінкою й включенням більше не губить комісію.
- **Гаманець: USD у підтвердженні.** Рядки «Сума, USD», «Комісія, USD», «Разом, USD» (лише коли ціни ввімкнено й доступні; повільний сервіс цін не затримує вікно понад 1,5 с).
- **Гаманець: сповіщення про результат транзакції.** Після відправки (EVM і Solana, зі сторінки гаманця чи від сайту) гаманець раз на 10 с перевіряє результат і показує «Транзакцію підтверджено» або «Транзакція не вдалася» (і сповіщення Windows, якщо вікно браузера не в фокусі). Опитування лише поки є очікувані транзакції.
- **Гаманець: знайти токени.** Кнопка «Знайти токени» шукає ERC-20 за недавніми переказами на рахунок і пропонує ті, що мають баланс і ще не у списку; токени, схожі на розсилку, позначено й показано в кінці. Нічого не додається без вашого вибору.
- **Гаманець: надійніші запасні RPC.** Запити для читання, на які вузол не відповів за 1,2 с, одразу дублюються на наступний вузол (перемагає перша успішна відповідь); відправлення транзакцій не дублюються.
- **Гаманець: налаштування й зручність.** «Повторно запитувати майстер-пароль» (через 2, 5, 10 або 15 хв; типово 2, як було), швидкі дії «Надіслати» й «Отримати» у верхній панелі гаманця (панель закріплена на достатньо великих вікнах), для нових гаманців типово відключаються сайти, якими не користувались 30 днів.
- **Авторизація через гаманець щоразу питає, яким рахунком увійти** (EVM `eth_requestAccounts`, `wallet_requestPermissions`, Solana `connect()`): вікно «Авторизація на сайті» з вибором рахунку показується навіть для сайту, який уже підключено; за замовчуванням пропонується поточний рахунок, інший вибір змінює підключення сайту (сайт отримує `accountsChanged`). Одночасні запити від сайту дають одне вікно. Тихі запити (`eth_accounts`, Solana `onlyIfTrusted`) вікна не показують. Вибір іде серед **усіх доступних рахунків** мережі (похідні від фрази й імпортовані; рахунки лише для перегляду не пропонуються, бо підписати ними неможливо). Якщо сховище заблоковано, спершу показується вікно розблокування, потім (коли рахунків кілька) вибір рахунку: раніше після розблокування сайт мовчки отримував рахунок за замовчуванням. Вимикається налаштуванням «Щоразу питати, яким рахунком увійти на сайті» на сторінці гаманця (`walletAskAccount`, типово ввімкнено).

Адаптивна верстка (три розкладки), `prefers-reduced-motion`. Дані сторінки віддаються лише їй (`startinfo`) і не містять сум гаманця, адрес і вкладок інкогніто.

Нижче лишилися мережі та гаманець, керування ШІ й журнал. Світла й темна теми, адаптація до вузьких вікон, `prefers-reduced-motion`.
- Приватність: вкладки інкогніто й вікон ШІ в списку не показуються, з адрес лишається лише хост (без шляху й параметрів); лічильники живуть лише в пам'яті й не зберігаються.
- Показується виділена приватна пам'ять процесів (Private Bytes); вона не збігається зі стовпцем «Пам'ять» у Диспетчері завдань, але зручна для порівняння між запусками.

## 1.32.0
- **Менше пам'яті блокувальника:** кеш рушія блокувальника (на новому профілі й раз на 7 діб) тепер будується в окремому процесі (`src/adblock-build.js`), а головний процес лише завантажує готовий файл. Раніше побудова піднімала RSS головного процесу на ≈160 МБ, і ця пам'ять не поверталась до кінця сеансу (приватна пам'ять у спокої на холодному профілі: 340 → 184 МБ). Якщо дочірній процес не впорався за 2 хв, діє стара поведінка (побудова в головному).
- **Сплячі вкладки:** час сну налаштовується (5, 15, 30, 60 або 120 хв; було фіксовано 15). Не присипляються активна, закріплені вкладки, вкладки з відео чи звуком (також без звуку) і вкладки з **незбереженим введенням** у формах (змінені текстові поля, прапорці, списки, редаговані блоки): раніше сон міг знищити набраний текст. Сторінки, що самі підставляють значення в поля, лишаються без сну (безпечний бік).
- **Стан функцій** (Налаштування → «Стан функцій»): кожна функція має мітку «Стабільна», «Бета» або «Експериментальна»; для гаманців EVM і Solana прямо сказано, що незалежного аудиту ще немає.

- **Режими обережності** (`src/wallet-safety.js`): «лише адресна книга» (отримувач має бути власним рахунком чи контактом); підтвердження великих сум (від порога в USD) з паузою 5 с — пауза також примусово перевіряється браузером; заборона переказу понад ліміт у USD; автовідключення сайтів, якими не користувались N днів. Діють для переказів зі сторінки гаманця (EVM, Solana, токени, NFT), не для транзакцій від сайтів. Зміна потребує майстер-пароля. Ліміти в USD працюють, лише коли ціна відома (інакше — попередження).
- **Резервна копія:** після створення гаманця браузер просить ввести три випадкові слова з аркуша (перевірка на боці браузера, 5 спроб, 5 хв), нагадування на сторінці, доки не підтверджено; **шифрований файл** `.w3irbackup` (`src/wallet-backup.js`: окремий пароль від 12 символів, scrypt N=2^17 + AES-256-GCM, заголовок автентифікований) із фразою, назвами рахунків, контактами й імпортованими ключами; відновлення з файлу на екрані створення гаманця (лише коли гаманця немає, усе з файлу перевіряється).
