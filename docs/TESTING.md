# Тестування

Автоматичний набір — `test/security.js` (**340 перевірок**, повний прогін ≈ 3–5 хв). Запускається всередині Electron, тому використовує справжні вікна, вкладки, сеанси й IPC.

```
set W3IR_USER_DATA=%TEMP%\w3ir-test-data
set W3IR_SMOKE=security
npx electron .
```

(у bash: `W3IR_USER_DATA="$(mktemp -d)/d" W3IR_SMOKE=security npx electron .`). Результат — рядки `[sec] PASS|FAIL …` і підсумок `[sec] RESULT: N passed, M failed`; код виходу 0.

## Ізоляція

- `W3IR_USER_DATA` (діє лише в непакетованій збірці) переносить дані на тимчасову теку й дає окреме блокування «одного екземпляра» — тести можна запускати, поки відкрито встановлений браузер. **Завжди** задавайте її: без неї запуск негайно завершується, коли вже працює встановлений браузер (спільне блокування), а тести торкалися б реальних даних.
- Усі тимчасові теки тестів створюються через `tmp()` і видаляються наприкінці прогону. Тести, що підміняють сховища (імпорт, гаманець, профілі), відновлюють їх після завершення.
- Системні діалоги й дії (`dialog.showMessageBox`, `shell.openPath`, `shell.openExternal`, `app.quit`) підмінюються заглушками там, де це потрібно.

## Інші сценарії

- `W3IR_SMOKE=1 W3IR_OUT=<тека>` запускає `test/smoke.js`: сайти в інтернеті (HTTPS-first, блокувальник, режим читання, сплячі вкладки, вертикальний режим, палітра, інкогніто), знімки екрана. Потрібен інтернет.
- Знімки екрана: тимчасово підмініть у `main.js` модуль `test/…` і зніміть `webContents.capturePage()` вікна інтерфейсу (`w.chrome`), вкладки (`w.wc()`) та оверлея (`w.overlay.webContents`). Не залишайте підміну в `main.js` після зйомки.
- Перевірка автооновлення на справжньому GitHub: емулювати стару версію через `autoUpdater.currentVersion` (екземпляр `SemVer` із пакета, який використовує `electron-updater`), `forceDevUpdateConfig = true`, окрема `updaterCacheDirName`.

## Корисні нотатки

- Нативні контекстні меню (`Menu.popup`) і перетягування мишею не автоматизуються: перевіряються їхні складові (пункти меню, команди, DOM-події), а не самі кліки.
- Після кожної зміни спершу виконайте `node --check` для змінених файлів — це ловить синтаксичні помилки швидше за повний прогін.
