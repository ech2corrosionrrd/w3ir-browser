# Тестування

Статичний аналіз: `npm run lint` (запускати перед випуском).

Вимірювання продуктивності: `npm run perf` ([PERFORMANCE.md](PERFORMANCE.md)).

Швидкі unit-тести без Electron: `npm run test:unit` (`build/run-unit.js` → `node --test`, секунди, без вікна; 147 перевірок: 146 passed, 1 skipped; працюють у CI до повного прогону). Покривають чисті модулі: `containers`, `wallet-limits` (ліміти гаманця, `solTokenDeltas`, `rpc-guard`), `util`, `urlrules`, `safe-fetch`, `qr`, `crypto-util`, `update-verify`, `injection-guard`, CSV історії EVM, `ftsQuery`, захист приватності `protection` (включно з Shield Privacy Center), парсери документів `docview` (Markdown, CSV/TSV, JSON, код), віджети `dashboard`, `startpage`; гаманець (`test/unit/wallet.test.js`): base58, суми Solana, Stake Program інструкції та перевірка Withdrawer, повідомлення транзакцій, SIWE, методи EIP-7702, failover RPC. Тест `places` потребує `node:sqlite` (Node 22.5+) і на старішому Node пропускається. Нові чисті функції додавайте сюди, а не в тести вікна. Вимірювання покриття коду: `npm run test:coverage` (V8 code coverage) із порогом ≥ 98% для модулів безпеки гаманця та криптографії.

Автоматичний набір (понад 1390 перевірок; усі проходять; для швидкої перевірки областей: `W3IR_ONLY=agentTests,updateTests`, назви — імена функцій у `test/security.js`) — `test/security.js` (запускач) і модульні області в `test/areas/*.js` (storage, web3, github, solana, fuzz, qr, places, injection, assistant, arweave, updates-threats, tabs, ai, i18n, misc; спільні помічники — `test/lib.js`) (повний прогін ≈ 3–5 хв). Запускається всередині Electron, тому використовує справжні вікна, вкладки, сеанси й IPC.

```
set W3IR_USER_DATA=%TEMP%\w3ir-test-data
set W3IR_SMOKE=security
npx electron .
```

(у bash: `W3IR_USER_DATA="$(mktemp -d)/d" W3IR_SMOKE=security npx electron .`). Коротко: **`npm test`** — те саме в тимчасовому профілі з виведенням лише збоїв і підсумку; код виходу 1, якщо є збої (`build/run-tests.js`). Результат — рядки `[sec] PASS|FAIL …` і підсумок `[sec] RESULT: N passed, M failed`; код виходу 0.

## Ізоляція

- `W3IR_USER_DATA` (діє лише в непакетованій збірці) переносить дані на тимчасову теку й дає окреме блокування «одного екземпляра» — тести можна запускати, поки відкрито встановлений браузер. **Завжди** задавайте її: без неї запуск негайно завершується, коли вже працює встановлений браузер (спільне блокування), а тести торкалися б реальних даних.
- Усі тимчасові теки тестів створюються через `tmp()` і видаляються наприкінці прогону. Тести, що підміняють сховища (імпорт, гаманець, профілі), відновлюють їх після завершення.
- Системні діалоги й дії (`dialog.showMessageBox`, `shell.openPath`, `shell.openExternal`, `app.quit`) підмінюються заглушками там, де це потрібно.

## Інші сценарії

- `W3IR_SMOKE=1 W3IR_OUT=<тека>` запускає `test/smoke.js`: сайти в інтернеті (HTTPS-first, блокувальник, режим читання, сплячі вкладки, вертикальний режим, палітра, інкогніто), знімки екрана. Потрібен інтернет.
- Знімки екрана: тимчасово підмініть у `main.js` модуль `test/…` і зніміть `webContents.capturePage()` вікна інтерфейсу (`w.chrome`), вкладки (`w.wc()`) та оверлея (`w.overlay.webContents`). Не залишайте підміну в `main.js` після зйомки.
- Перевірка автооновлення на справжньому GitHub: емулювати стару версію через `autoUpdater.currentVersion` (екземпляр `SemVer` із пакета, який використовує `electron-updater`), `forceDevUpdateConfig = true`, окрема `updaterCacheDirName`.

## Тест встановленої збірки (CDP)

Окремий сценарій `test/installed-cdp.js` перевіряє **справжню встановлену** збірку (не dev-режим):

0. Встановлена збірка не запускається з параметрами налагодження (див. `src/launch-guard.js`); тест упакованої збірки виконує розробник за приватною інструкцією.
1. Запустіть другий екземпляр у **тимчасовому профілі** (ваш браузер і дані не чіпаються): PowerShell — `Start-Process "C:\Program Files\W3IR Browser\W3IR Browser.exe" -ArgumentList '--user-data-dir="<тека>"','--remote-debugging-port=9333','--remote-allow-origins=*'` (з Bash цей запуск не працює).
2. Запустіть клієнт CDP: `set ELECTRON_RUN_AS_NODE=1` і `node_modules\electron\dist\electron.exe test\installed-cdp.js` (Node 24 із Electron має `WebSocket`; зовнішніх залежностей немає). `SHOTS=<тека>` — зберегти скриншоти.
3. Сценарій перевіряє: версію й User-Agent, нову вкладку (бренд), усі внутрішні сторінки, HTTPS-first, ізоляцію вебсторінок від API браузера, завантаження списків загроз і пінг RPC, розділений екран, сервер MCP (401/403, `initialize`, інструменти, справжнє вікно підтвердження, заборону введення в поле пароля на `github.com/login`) і наприкінці закриває екземпляр командою `Browser.close`.
   Для 1.44.0 додано перевірки нових функцій: провайдер `window.arweaveWallet` на вебсторінці (у свіжому тестовому профілі сценарій сам створює сховище паролів і гаманець, бо без гаманця провайдер не вводиться), перемикачі Shield «Вимкнути JavaScript» і «Блокувати сторонні кадри» на локальному тестовому сервері, Glance (Alt+клік через `Input.dispatchMouseEvent` відкриває окрему ціль без моста гаманця), Tab Stash (відкласти й відновити набір) і, починаючи з 1.44.1, наявність цих розділів у довідці. Esc і Ctrl+Enter у Glance через CDP до головного процесу не доходять, тому їх перевіряє область `productivityTests` (`sendInputEvent`). Стан на 1.44.6: 72 з 72.

Те саме можна робити з **локальною упакованою збіркою до випуску**: `npm run pack` збирає `dist\win-unpacked\W3IR Browser.exe` (без інсталятора й публікації), на ній ті самі кроки й `EXPECT_VERSION=<версія>`; саме так перевірено 1.16.0 (54 з 54).

Застереження: тестове вікно **видиме** — не працюйте в ньому вручну; завершувати слід лише процеси з `--user-data-dir` тестового профілю. Адреси внутрішніх сторінок у CDP мають кінцевий `/`; `Page.captureScreenshot` для прихованої вкладки не повертається (потрібен тайм-аут).

## Нотатки про ручні дії

Програмні події миші (`sendInputEvent` без паузи між натисканням і відпусканням) **не відтворюють справжній клік**: у людини між `mousedown` і `mouseup` проходить 80–300 мс, за які приходять оновлення стану. Для кнопок інтерфейсу перевіряйте «повільний» клік (`await sleep(150)` між подіями), як у `tabCloseTests`. Так знайдено помилку з хрестиком вкладки (1.16.1).

## Корисні нотатки

- Нативні контекстні меню (`Menu.popup`) і перетягування мишею не автоматизуються: перевіряються їхні складові (пункти меню, команди, DOM-події), а не самі кліки.
- Після кожної зміни спершу виконайте `node --check` для змінених файлів — це ловить синтаксичні помилки швидше за повний прогін.

## Перевірка на справжніх мережах (без коштів)

Автотести гаманця використовують імітації RPC. Щоб переконатися, що побудовані гаманцем транзакції Solana приймає справжнє середовище виконання, є два окремі сценарії (запуск через Electron як Node, потрібен інтернет):

- `ELECTRON_RUN_AS_NODE=1 node_modules/electron/dist/electron.exe build/mainnet-sim-check.js` — **симуляція на mainnet** без підписів і коштів: знаходить справжнього власника USDC, будує створення токен-акаунта (ATA) + `TransferChecked` і переказ SOL, виконує `simulateTransaction` із `sigVerify:false`; мережа має прийняти правильні варіанти й відхилити хибні (неіснуючий ATA, неправильні decimals, сума більша за баланс). Публічні вузли обмежують частоту запитів — скрипт сам повторює спроби; код виходу 2 означає «пропущено» (немає підходящого власника чи вузол відмовив).
- `ELECTRON_RUN_AS_NODE=1 node_modules/electron/dist/electron.exe build/devnet-check.js [rpc]` — **повний цикл на Devnet з реальними транзакціями**: безкоштовний airdrop, переказ SOL, створення токена, асоційованих акаунтів, випуск і переказ токенів. Потребує, щоб faucet видав тестові SOL (публічний faucet часто обмежує за IP: код виходу 2 — повторіть пізніше або вкажіть інший RPC).

Нові області гаманця (кожна запускається окремо через `W3IR_ONLY=<функція>`): `nftTests`, `nftSourcesTests` (безпечне завантаження, ?ext= Irys, запасні RPC), `signguardTests`, `approvalsTests`, `portfolioTests`, `simulateTests`, `solanaExtrasTests` (імена .sol, пріоритетна комісія), `historyEvmTests` (історія EVM, розсилки, CSV). Вони працюють на імітаціях RPC; справжню мережу перевіряють `build/check-rpc.js` і скрипти mainnet/devnet вище.

Збірка інсталятора на сервері GitHub: workflow `Build` (`.github/workflows/build.yml`) запускається вручну чи за тегом; `npm run release:ci` бере його артефакт для поточного коміту (див. [RELEASING.md](RELEASING.md)).

`test/areas/fuzz.js` — fuzz-перевірки парсерів із фіксованим зерном (запускаються в складі `npm test`).
