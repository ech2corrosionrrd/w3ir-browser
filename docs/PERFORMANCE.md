# Продуктивність: базові цифри

Вимірювання повторюються командою `npm run perf` (Windows, потрібна робоча стільниця; на пів хвилини двічі з'являється вікно тимчасової копії браузера з окремим профілем, ваші дані не чіпаються). Скрипти: `build/perf.js`, `build/perf-ipc.js`. Вивід — JSON.

## Базові значення (2026-10-18, v1.31.0)

Стенд: Windows 11 (10.0.26300), 16 логічних ядер, 32 ГБ ОЗП, Electron 44.9.0 (Node 24.22). Один прогін, тобто це орієнтир, а не гарантія; відхилення між запусками 10–30%.

| Що міряється | Значення | Коментар |
|---|---|---|
| `Store.flush`, JSON ≈10 КБ / ≈500 КБ / ≈5 МБ | 1,4 / 3,7 / 31 мс (p50); p95 1,9 / 6,1 / 48 мс | атомарний запис: тимчасовий файл → `fsync` → перейменування, синхронно в головному процесі |
| Синхронний IPC (`sendSync`, основа `wallet:init`) | 0,10 мс (p50), 0,20 мс (p95) | порожній обробник: міряється канал; сам обробник O(1) |
| Старт: поява цілі інтерфейсу (`w3ir://ui/index.html`) | ≈0,3 с | момент, коли вікно створено, а не коли все намальовано й завантажено |
| Пам'ять у спокої, **приватна** (теплий профіль) | **≈184 МБ** | головний 93, GPU 32, мережа 7, 3 рендерери 51 |
| Пам'ять у спокої, робочий набір | ≈641 МБ | завищений, див. нижче |
| Пам'ять із 5 вкладками (локальна сторінка), приватна | ≈435 МБ | головний 248, рендерери 140, GPU 39 |
| Додатково на одну вкладку, приватна | ≈50 МБ | приблизно 18 МБ рендерер і ≈30 МБ головний процес |
| Пам'ять у спокої на **холодному** профілі, приватна | ≈340 МБ | головний процес 247: рушій блокувальника будується зі списків |

## Як читати

- **Пам'ять.** `ws` (робочий набір, як у Диспетчері завдань) завищений: спільні сторінки Chromium враховуються в кожному процесі, тому раніше здавалось, що браузер у спокої займає ≈800 МБ. Реальнішою є **приватна** пам'ять (`WorkingSetPrivate`), її й варто порівнювати між релізами.
- **Теплий і холодний профіль.** Холодний це новий профіль без кешу `adblock-engine.bin`. Теплий це щоденний запуск з кешем. Різницю дає блокувальник реклами: побудова рушія зі списків піднімає пам'ять головного процесу на ≈170 МБ (повільніше й важче), а завантаження з кешу коштує ≈10 МБ і ≈16 мс. На практиці побудова трапляється на новому профілі й раз на 7 діб (кеш вважається застарілим після `MAX_AGE`, див. `src/adblock.js`).
- **Старт** міряє час до появи цілі CDP інтерфейсу. Повний час до готовності довший; фонові завдання (оновлення, списки загроз, блокувальник) стартують із затримкою й тут не враховані.
- **`wallet:init`** викликається синхронно з кожної сторінки під час завантаження. Вартість канала ≈0,1 мс, тож затримку завантаження сторінок це не пояснює.

## Що з цього випливає

1. **Блокувальник не винен у зростанні при відкритті вкладок.** Перевірено окремо: зіставлення запитів і косметичні фільтри додають ≈1 МБ. Модулі застосунку (`ethers`, гаманець, Solana, загрози, PDF, агент) разом підвантажуються за ≈20 МБ.
2. **Головний процес росте на ≈30 МБ на вкладку.** Схоже, це накладні витрати Chromium на кожен `WebContents` (не наш код); причину не розкладено далі.
3. **Раз на 7 діб побудова рушія блокувальника тимчасово дає +170 МБ у головному процесі.** Чи повертається ця пам'ять системі після побудови, не перевірялося. Якщо ні, браузер, який працює днями, тримає зайві ≈150 МБ. Варіанти: будувати рушій у `worker_threads`/utility-процесі або оновлювати кеш лише при старті. Це кандидат на окрему задачу після перевірки на довгому сеансі.
4. Цифри не показують проблеми, що вимагала б термінового виправлення: ≈184 МБ приватної пам'яті в спокої нормальні для Chromium-браузера.

## Що ще не міряється

- Час повного завантаження сторінок і холодний старт після перезавантаження ПК.
- Споживання процесора й енергії; інкогніто, розширення Chrome, відкритий гаманець.
- Поведінка на довгому сеансі (дні роботи, утримання пам'яті після щотижневої побудови рушія).
