# Продуктивність: базові цифри

Вимірювання повторюються командою `npm run perf` (Windows, потрібна робоча стільниця; на хвилину з'являється вікно тимчасової копії браузера з окремим профілем, ваші дані не чіпаються). Скрипти: `build/perf.js`, `build/perf-ipc.js`. Вивід — JSON.

## Базові значення (2026-10-18, v1.31.0)

Стенд: Windows 11 (10.0.26300), 16 логічних ядер, 32 ГБ ОЗП, Electron 44.9.0 (Node 24.22). Один прогін, тобто це орієнтир, а не гарантія; відхилення між запусками 10–30%.

| Що міряється | p50 | p95 | Коментар |
|---|---|---|---|
| `Store.flush`, JSON ≈10 КБ | 1,4 мс | 1,9 мс | атомарний запис: тимчасовий файл → `fsync` → перейменування |
| `Store.flush`, JSON ≈500 КБ | 3,7 мс | 6,1 мс | |
| `Store.flush`, JSON ≈5 МБ | 31 мс | 48 мс | синхронний запис у головному процесі |
| Синхронний IPC (`sendSync`, основа `wallet:init`) | 0,10 мс | 0,20 мс | порожній обробник: міряється канал; сам обробник O(1) |
| Старт: поява цілі інтерфейсу (`w3ir://ui/index.html`) | ≈0,3 с | | момент, коли вікно створено, а не коли все намальовано й завантажено |
| Пам'ять усіх процесів у спокої (через 4 с після старту) | ≈795 МБ | | сума робочих наборів (див. застереження) |
| Пам'ять із 5 вкладками (локальна сторінка) | ≈1357 МБ | | ≈112 МБ на вкладку |

## Як читати

- **Пам'ять** це сума `WorkingSetSize` усіх процесів браузера (головний, GPU, мережа, рендерери). Вона **завищена**: спільні сторінки пам'яті (бібліотеки Chromium) враховуються в кожному процесі. Для порівняння між версіями цифра годиться, як абсолют — ні (Диспетчер завдань покаже менше).
- **Старт** міряє час до появи цілі CDP інтерфейсу. Повний час до готовності (відображений вміст, фонові завдання) довший; фонові завдання (оновлення, списки загроз, блокувальник) стартують із затримкою й тут не враховані.
- **`Store.flush`** виконується синхронно в головному процесі. Для малих сховищ це майже непомітно. Історія вже лежить у SQLite, а налаштування й інші списки в JSON; якщо якийсь JSON зросте до мегабайтів, запис стане помітним (≈30 мс на 5 МБ).
- **`wallet:init`** викликається синхронно з кожної сторінки під час завантаження. Вартість канала ≈0,1 мс, тож затримку завантаження сторінок це не пояснює. Якщо сторінки сповільняться, дивіться інше.

## Що це означає для роботи

- Пам'ять у спокої близько 0,8 ГБ видається великою для браузера без вкладок. Варто подивитися, що саме займає: блокувальник реклами (рушій Ghostery), списки загроз, внутрішні сторінки. Це кандидат на окреме дослідження, а не на висновок: цифра нерозкладена за процесами.
- Для порівняння між релізами запускайте `npm run perf` перед випуском і не допускайте погіршення більш ніж на ~20% без пояснення.

## Що ще не міряється

- Час повного завантаження сторінок і холодний старт після перезавантаження ПК.
- Споживання процесора, енергії та пам'яті в інкогніто, з розширеннями Chrome, з відкритим гаманцем.
- Розкладка пам'яті за процесами (потрібен `app.getAppMetrics()` з головного процесу).
