# Відповідь на зовнішній аудит (2026-10-16)

Зовнішній аудит (лише читання коду, 1.16.2) знайшов 5 «середніх» проблем і ряд дрібних. Кожне твердження перевірено за кодом; нижче вердикт і що зроблено у **1.17.0**. Усі виправлення мають автотести (`auditTests` у `test/security.js`).

## «Середні»

| Твердження | Вердикт | Що зроблено |
|---|---|---|
| Спливаючі вікна без адресного рядка (фішинг) | **Частково.** Вікно справді безадресне, але «завжди відкривати вкладкою» зламало б вхід через OAuth-вікна й dApp-гаманці (`window.opener`) | Вікно лишається, але в заголовку **завжди справжнє походження** (`127.0.0.1:порт — заголовок`, сайт підробити не може); навігація лише http/https (без `file:`/`w3ir:`); вкладені `window.open` стають вкладками |
| Запуск завантажень без попередження | **Так** | Відкриття `.exe .msi .bat .cmd .ps1 .js .lnk .hta .iso` та ін. — лише після підтвердження (за замовчуванням «Скасувати»); безпечні типи відкриваються як і раніше |
| Спільні IPC-команди для всіх `w3ir://` | **Так, як захист у глибину** (XSS у внутрішніх сторінках не знайдено: `innerHTML` немає, CSP без inline) | Таблиця `PAGE_ONLY` у `ipc.js`: `settings:set`, `clear`, `ext:*`, `reader:get`, `history:*` тощо — лише зі своєї сторінки. `frame-ancestors` не потрібен: IPC дозволено лише головному кадру, у iframe він недоступний (перевірено тестом на встановленій збірці) |
| Немає резервної копії vault і Store | **Так** | `writeAtomic` тепер з `fsync`; Store і `vault.bin`/`vault.pepper` зберігають `.bak` (Store — не частіше, ніж раз на 10 хв); пошкоджений файл **не стирається** — його перейменовано в `.corrupt-<час>`, дані беруться з `.bak`. Сховище паролів відновлюється з `.bak` лише коли файл не розбирається як JSON (обрізаний запис); підмінений файл із хибними параметрами KDF відхиляється, а не «лікується» |
| Підпис оновлень неповний | **Частково.** Hash інсталятора входить у підписане повідомлення, тому ім'я файлу не потрібне; пониження версії блокує оновлювач. Справді немає: Authenticode (потрібен сертифікат), ротації ключа, терміну дії підпису | Не змінювалося: зміна формату підпису зламала б уже встановлені копії. Лишається в планах: резервний ключ і ротація (потрібна копія приватного ключа поза комп'ютером), Authenticode/SignPath |

## «Дрібніші»

| Твердження | Вердикт | Дія |
|---|---|---|
| SSRF-перевірка агента лише за hostname | **Так** | Додано перевірку DNS: домен, що вказує на локальну/приватну адресу (IPv4/IPv6/відображена), відхиляється до запиту користувачу. Не повна гарантія (адреса може змінитися після перевірки) |
| Глобальний лічильник невдалих входів MCP | **Прийнято як є.** Усі запити приходять з 127.0.0.1, розрізнити клієнтів неможливо; токен 256-бітний, лічильник лише обмежує перебір | — |
| Reader: чорний список тегів, Readability у головному світі | **Так (білий список)** | Санітизатор переписано на білий список тегів/атрибутів; невідомі теги замінюються вмістом; посилання лише `http(s)`/`#`, зображення `http(s)`/`data:image/png|jpeg|gif|webp`. CSP внутрішніх сторінок і раніше блокує inline-скрипти |
| Зовнішні схеми (`vscode:`) без жесту користувача | **Частково.** Підтвердження було завжди; спам діалогами був можливий | Одне вікно підтвердження за раз |
| Розпаковані розширення: `allowFileAccess: true` | **Так** | Вимкнено |
| Vault: 2-хв вікно автентифікації, секрети в JS-рядках | **Прийнято.** Задокументовано в `SECURITY.md`; JS не дає гарантованого стирання пам'яті | — |
| Гаманець: typed data обрізається, комісія з RPC | **Прийнято як обмеження.** Є розшифровка й попередження для Permit/Order; незалежний аудит гаманця лишається в планах | — |
| Sync: відкат на старий файл | **Низький ризик:** злиття об'єднує записи (надгробки, мітки часу), відкат не стирає новіші локальні дані | — |
| `W3IR_SMOKE` у продакшн-вході | **Так** (не експлуатується, бо `test/` не пакується, але зайве) | Хук підключається лише в непакетованій збірці |

## «Архітектурні»

| Твердження | Вердикт |
|---|---|
| Великі файли | Так; розділений екран і доступ ШІ вже винесено в міксини. Подальший поділ — у плані |
| Один тестовий файл, лише в Electron | Так; є `npm test`. Поділ за областями й unit-тести без Electron (чисті функції) — у плані |
| Перевірки origin розкидані по `ipc.js` | Частково виправлено таблицею `PAGE_ONLY` для спільних команд; повна централізація — у плані |
| Дублювання `normOrigin`/`clean`/`siteKey` | Так, дрібне; у плані |
| Store серіалізує весь JSON, `wallet:init` через `sendSync` | Не виміряно: історія 2 тис. записів (~1 МБ), запис відкладений на 400 мс; перегляд за потреби |

## Не перевірено аудитом

`ui/renderer.js`, `ui/overlay.js`, `app-window.js`, `context.js`, інструменти MCP, `adblock.js`, `tab-groups.js`, `split-view.js`, `dashboard.js`, `build/*.js`. Їх покривають власні тести (448 перевірок) і тест встановленої збірки (`test/installed-cdp.js`), але незалежного огляду вони не мали.
