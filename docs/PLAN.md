# План розвитку

_Оновлено 2026-10-17 (версія 1.20.1). Основа: критичний аналіз, огляд репозиторіїв ([RESEARCH.md](RESEARCH.md)), бренд ([BRANDING.md](BRANDING.md)), зовнішній аудит ([AUDIT.md](AUDIT.md)), поточний стан — [ROADMAP.md](ROADMAP.md)._

## Ключове рішення та орієнтири

1. **ШІ підключається через Claude Code по MCP** (підписка власника, без сторонніх платних API-ключів) та перспективні локальні моделі (Ollama) з суворою ізоляцією даних, забороною введення паролів і підтвердженням кожного домену.
2. **Web3 та Мультичейн (EVM + Solana)**: розвиток вбудованого гаманця для підтримки EVM та **Solana** із захистом від дрейнерів і підтвердженням кожної транзакції.
3. **Децентралізоване сховище: Arweave (Irys)**:
   - **Primary & Mandatory Storage**: для всіх NFT-колекцій, метаданих JSON і Web3-медіа (PNG, SVG, аудіо, відео) обов'язковим постійним сховищем є **Arweave** (через Irys / `node1.irys.xyz` або нативні шлюзи `arweave.net`).
   - **Повна відмова від Pinata / IPFS**: виключає щомісячні витрати на підписку, ліміти шлюзів та помилки 429 rate-limiting.
4. **Безпека й автономність понад усе**: усі функції працюють локально, без зовнішніх серверів розробника чи телеметрії.
5. **Кожна функція — з повним покриттям автотестами** (490+ тестів у `test/security.js`), документацією та чистим кодом без сторонніх фреймворків.

## Етап 6. Solana Web3 Інтеграція & Децентралізоване сховище (Новий пріоритет)

### 6.1. Децентралізоване сховище для NFT та метаданих (Arweave / Irys) — Версія 1.21.0
* **Постійне сховище Arweave**:
  * Реалізація обробника протоколу `ar://<txId>` в `src/context.js` через `protocol.handle('ar', ...)` з резолвінгом через пул надійних шлюзів (`https://gateway.irys.xyz/`, `https://arweave.net/`).
  * Новий модуль `src/arweave.js`: валідація txId (43 символи base64url), запити до Arweave GraphQL API, резолвінг метаданих та кешування.
  * Інтеграція з Irys SDK (`node1.irys.xyz`) для швидкого завантаження метаданих до 100 КБ.
* **Галерея NFT у гаманці**:
  * Відображення NFT на сторінці `w3ir://wallet` та Панелі для EVM (ERC-721/1155) і Solana (Metaplex).
  * Парсинг `tokenURI` з пріоритетом Arweave-сховища (відмова від залежності від платних API OpenSea/Alchemy).
  * Повне виключення Pinata/IPFS згідно з глобальною директивою.
* **Автотести**: модуль `test/areas/arweave.js` з перевіркою валідації адрес, резолвінгу `ar://` та парсингу метаданих.

### 6.2. Провайдер та архітектура Solana — Версія 1.22.0
* **Стандарти**:
  * Реалізація стандарту `anza-xyz/wallet-standard` (`@wallet-standard/core`) та реєстрація гаманця через `wallet-standard:register-wallet`.
  * Інжекція `window.solana` (сумісність із Phantom / Solflare API).
* **Ключі та адреси**:
  * Нативна деривація ключів Solana у `node:crypto` за стандартом SLIP-0010: `m/44'/501'/0'/0'` (Ed25519) від фрази відновлення у `src/vault.js` без сторонніх важких бібліотек.
  * Підтримка експорту/імпорту ключів у форматі Base58.
* **Запити сторінок (RPC-методи)**:
  * `connect`, `disconnect`: авторизація сайту з показом довіреного вікна підтвердження.
  * `signTransaction`, `signAllTransactions`, `signAndSendTransaction`: серіалізація та нативний підпис транзакцій Solana.
  * `signMessage`: підпис довільних повідомлень для автентифікації на dApp.
* **Безпека транзакцій Solana (Drainer Protection — патерни WalletGuard & Blowfish)**:
  * Розшифровка інструкцій: System Program (переказ SOL), SPL Token Program (переказ токенів, створення ATA).
  * Попередження про небезпечні операції: `SetAuthority` (зміна власника токена чи акаунта), закриття акаунтів, взаємодія з невідомими програмами.
  * Попередня симуляція транзакції через RPC (`simulateTransaction`) перед запитом згоди користувача (показ зміни балансів SOL і токенів).
* **Мережі**:
  * Mainnet-Beta (`https://api.mainnet-beta.solana.com` + альтернативні швидкі ноди).
  * Devnet, Testnet, власні RPC.

## Етап 7. Продуктивність, Ядро та Апаратна Безпека

### 7.1. Перехід на SQLite (FTS5) для історії та закладок — Версія 1.23.0
* **Ціль**: замінити масивні JSON-файли (`history.json`, `bookmarks.json`) на нативний `node:sqlite` (доступний у Node 24 в складі Electron 41).
* **Архітектура за зразком Firefox Places & Chromium**:
  * Таблиця `history` з індексами та розрахунком ваги за алгоритмом **Frecency** (формула: частота візитів × коефіцієнт свіжості за експоненційним спадом).
  * Віртуальна таблиця швидкого повнотекстового пошуку `history_fts USING fts5` з автоматичними тригерами `AFTER INSERT/DELETE`.
  * Зниження навантаження на диск (запис лише змінених рядків, без повної серіалізації JSON на кожен перехід) та миттєва видача підказок в адресному рядку.

### 7.2. Апаратні гаманці (Hardware Wallets via WebHID / WebUSB) — Версія 1.28.0 (відкладено)
* **Чому після ШІ:** підпис транзакцій на пристрої не можна чесно перевірити без фізичного Ledger/Trezor (APDU-обмін, екран пристрою, WebHID у Electron). Реалізація має самоперевірку підписів (адреса відновлюється з підпису до відправки), але вимагає тесту на справжньому пристрої; тому пункт пересунуто за ШІ-частину, яка повністю покривається тестами.
* **Підтримка Ledger та Trezor** для EVM та Solana.
* Використання нативного WebHID через подію сесії Electron `session.on('select-hid-device')` та бібліотеки `@ledgerhq/hw-transport-webhid` / `@trezor/connect-web`.
* Підпис транзакцій безпосередньо на захищеному пристрої без потрапляння закритого ключа в пам'ять процесу.

### 7.3. Локальні ШІ-моделі (Ollama) та Захист від Prompt Injection — Версія 1.24.0
* Підтримка підключення локальних моделей через локальний MCP-сервер W3IR та HTTP API Ollama (`http://localhost:11434`).
* Санітизація веб-сторінок від прихованих інструкцій (патерни `protectai/rebuff` та `llm-guard`: фільтрація `display:none`, прихованих шарів та спроб перезапису системних інструкцій).
