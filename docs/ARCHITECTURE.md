# Архітектура

Electron 44 (Chromium 152 + Node 24). Увесь код головного процесу — CommonJS у `src/`, інтерфейс — звичайні HTML/CSS/JS без збирача.

## Процеси та вікна

| Компонент | Реалізація |
|---|---|
| Головний процес | `main.js` → `ProfileManager` → контексти профілів → `AppWindow` |
| Вікно браузера | `BrowserWindow`, у ньому сторінка інтерфейсу `w3ir://ui/index.html` (вкладки, панель, закладки, пошук на сторінці) |
| Вкладка | окремий `WebContentsView` (sandbox, contextIsolation), preload `page-preload.js` |
| Оверлей | один `WebContentsView` над вкладками (`w3ir://ui/overlay.html`) для меню, підказок, палітри, панелей і вікон підтвердження |
| Внутрішні сторінки | протокол `w3ir://<назва>` обслуговує теку `pages/`; `w3ir://ui/…` — теку `ui/` |

Схема `w3ir` зареєстрована як privileged (standard, secure, fetch). Схема `ar` зареєстрована як privileged (secure, supportFetchAPI, corsEnabled — навмисно без `standard`, що запобігає примусовому переведенню base64url хешів транзакцій у нижній регістр Chromium). Для обслуговування викликається `ses.protocol.handle` у кожному сеансі (див. `setupSession` у `src/context.js`). Користувацькі скрипти не інжектуються; усі внутрішні сторінки працюють під суворим CSP (`script-src 'self'`, без inline).

| `adblock-build.js` | компіляція кешу рушія блокувальника в окремому дочірньому процесі для оптимізації пам'яті |

## Контексти профілів

`ProfileManager.ctx(id)` створює об'єкт контексту (`createContext`) зі своїми: `settingsStore`, `bookmarksStore`, `historyStore`, `sessionStore`, `windowStore`, `permsStore`, `extStore`, `Downloads`, `Vault`, `Wallet`, `Sync`, `GitHub`, `Threats` та сеансом Electron (основний профіль — `session.defaultSession`, інші — `persist:profile-<id>`). Теку даних основного профілю складає `userData`; решти — `userData/profiles/<id>`.

Спільні для всіх профілів (`manager.shared`): рушій блокувальника та preload косметичних фільтрів, список сеансів, списки загроз. IPC-обробники реєструються один раз і знаходять потрібний контекст за відправником (`manager.ctxOf(webContents)`).

Інкогніто — окреме вікно профілю з тимчасовим сеансом (без `persist:`), пам'яттю дозволів у `ses.__w3irPerms`; після закриття сеанс очищується.

## Конвеєр запитів (webRequest, `setupSession`)

Головний кадр (GET): `stripTracking` → `upgradeHttps` (HTTPS-first, запам'ятовує невдалі хости) → перевірка загроз (`redirectURL` на `w3ir://warning?…`) → редирект, якщо адресу змінено.
Підзапити: блокувальник Ghostery (`onBeforeRequest`, `onHeadersReceived`), виняток для сайту (`adblockAllowed(topHost)`), лічильник заблокованого на вкладці. Заголовки: `Sec-GPC`, `DNT`.

## IPC

| Канал | Напрямок | Хто може викликати |
|---|---|---|
| `cmd` | інтерфейс/оверлей → `AppWindow.exec` | лише вікно інтерфейсу й оверлей цього вікна |
| `suggest` | інтерфейс → підказки адреси | вікно інтерфейсу |
| `internal` | внутрішні сторінки → `ipc.js` | лише головний кадр вкладки з адресою `w3ir://…`; кожна група імен прив'язана до конкретної сторінки (`vault:*` ← passwords; `wallet:*` ← wallet; `sync:*`, `github:*`, `update:*`, `sites:*`, `safe:status/update` ← settings; `safe:proceed/trust` ← warning; `import:*` ← import; `profiles:*` ← profiles) |
| `dashboard:*` | сторінка панелі → `dashboard.js` | лише `w3ir://dashboard`, не з вікна агента |
| `agent:*` | сторінка налаштувань → `agent.js` | лише `w3ir://settings`, не з вікна агента |
| `wallet:init` (sync), `wallet:request` | preload вкладки → гаманець | головний кадр звичайної (не приватної) вкладки на https/localhost |
| `vault:captured` | preload вкладки → пропозиція зберегти пароль | головний кадр, не інкогніто |
| події в інтерфейс | `state`, `toast`, `savebar`, `find-*`, `group-edit`, `overlay`, `url-blur`, `focus-url` | дозволені списком у `preload.js` |

Origin завжди визначає браузер за адресою кадру відправника, а не за даними повідомлення.

## Оверлеї

Прив'язані під панеллю інструментів на всю область: `menu`, `vault`, `github`, `site` (константа `ANCHORED_OVERLAYS`); на все вікно: `palette`, `approve`; невелика прямокутна область: `suggest`. `approve` (гаманець) не закривається кліком повз вікно; закриття = відхилення. Екрани паролів, гаманця й оверлеї `vault`/`approve` вмикають `setContentProtection`.

## Повноекранний режим

Два незалежні поняття: `win.isFullScreen()` (вікно на весь екран: F11/меню, прапорець `userFs`) і `htmlFullscreen` (сайт у власному повноекранному режимі: інтерфейс ховається, вкладка займає все вікно). Подія `enter-html-full-screen` вмикає повний екран вікна й `htmlFullscreen`; вихід — `exitHtmlFullscreen()`: скидає прапорець, закриває повний екран у всіх вкладках (`document.exitFullscreen()`), знімає повний екран вікна, якщо його не вмикав користувач, і перераховує розкладку. Його викликають: Esc, F11/меню, перемикання й закриття вкладки, подія `leave-full-screen` вікна.

## Стан інтерфейсу

`AppWindow.sendState()` (з 30-мс згладжуванням) надсилає в інтерфейс повний знімок: вкладки, групи, закладки, статуси паролів/GitHub/оновлення/завантажень, профіль. `ui/renderer.js` відмальовує його з нуля при кожному оновленні (редагування назви групи тримається окремою змінною).

## Дані

Усі JSON-файли пишуться атомарно (тимчасовий файл + `rename`) з відкладенням 400 мс; `flushAll()` викликається при виході. Секрети (сховище паролів, токен GitHub, ключ синхронізації) шифруються (див. [SECURITY.md](SECURITY.md)). Перелік файлів — у [README](../README.md).

## Де зберігаються ключі й дані

Усе лежить у теці профілю (`userData`; додаткові профілі — у `profiles/<id>/`, кожен зі своїм сховищем). Нижче — що є секретом, у якому вигляді він на диску та коли зникає з пам'яті.

| Що | Файл | Як захищено | Життя в пам'яті | Код |
|---|---|---|---|---|
| Паролі, нотатки, TOTP-секрети | `vault.bin` (+ `.bak`) | AES-256-GCM; ключ = scrypt (N=2^17, r=8, p=1) від майстер-пароля та «перцю»; заголовок з параметрами KDF входить в AAD, тому підміна виявляється | ключ і розшифровані дані лише в головному процесі; при блокуванні ключ обнуляється (`fill(0)`), дані видаляються; автоблокування за простою (за замовчуванням 15 хв) | `src/vault.js`, `src/crypto-util.js` |
| «Перець» сховища | `vault.pepper` | зашифровано DPAPI (`safeStorage`) — файл сховища марний без акаунта Windows | читається під час розблокування | `src/vault.js` |
| Seed і адреси гаманця, підключення сайтів | секція `wallet` усередині `vault.bin` | ті самі шифрування й блокування, що й для паролів; окремого файлу ключів немає. У пам’яті після розблокування розділ не лежить в об’єкті паролів, а запечатаний окремим буфером (AES-256-GCM, AAD `w3ir-wallet-section`) | доступні лише розблокованими; при блокуванні сайти отримують порожній список рахунків | `src/wallet.js`, `src/vault.js` |
| Токен GitHub | `github.token` | DPAPI (`safeStorage`); якщо захищене сховище недоступне — токен не зберігається | у пам'яті після зчитування | `src/github.js` |
| Ключ синхронізації | `sync.key` | DPAPI (`safeStorage`); вміст синхронізованої теки шифрується цим ключем | у пам'яті під час синхронізації | `src/sync.js` |
| Cookie, localStorage, кеш сайтів | `Network/`, `Local Storage/`, `Cache/` тощо | керує Chromium (os_crypt/DPAPI) | у процесах вкладок | Chromium |
| Історія, закладки | `places.sqlite` | не шифрується (не секрет рівня паролів); у вікні інкогніто не записується | — | `src/places.js` |
| Налаштування, сесія, вікно | `settings.json`, `session.json`, `window.json` | не шифруються; секретів не містять | — | `src/store.js` |
| Публічний ключ перевірки оновлень | у коді застосунку | підпис кожного інсталятора перевіряється до запуску | — | `src/updater.js` |
| Журнал збоїв | `crash.log` (ротація) | лише на диску, ніколи не надсилається; ключі, токени, seed-подібні послідовності слів і шляхи домашньої теки редагуються | — | `src/crash-log.js` |

Правила:
- Приватні ключі підпису оновлень не потрапляють у репозиторій, секрети CI чи застосунок — у застосунку лише публічний ключ.
- Усі JSON-файли пишуться атомарно (тимчасовий файл + `rename`); для сховища та «перцю» зберігається резервна копія `.bak`.
- Формат сховища, синхронізації й підпису оновлень змінюється лише зі шляхом міграції та тестом старого формату.
- Резервні копії seed-фрази й експорт сховища власник зберігає офлайн, поза комп'ютером.

## Мережеві запити браузера

Браузер сам нічого не надсилає розробнику: немає телеметрії, звітів про збої (`crashReporter` не запускається; `crash.log` лишається на диску), Google Safe Browsing чи синхронізації з хмарою за замовчуванням. Власні запити застосунку (поза сторінками, які відкриває користувач):

| Адреса | Навіщо | Коли | Де в коді |
|---|---|---|---|
| `raw.githubusercontent.com/ghostery/adblocker/…` | правила блокувальника реклами | при старті, якщо кеш відсутній чи застарів | `src/adblock.js` |
| `malware-filter.gitlab.io`, `raw.githubusercontent.com` (Phishing.Database, MetaMask, polkadot-js) | списки шкідливих і фішингових доменів | через ≈15 с після старту, якщо списки старші за добу; далі раз на добу | `src/threats.js` |
| GitHub (канал `ech2corrosionrrd/w3ir-browser`) | перевірка оновлень | через ≈20 с після старту, далі кожні 6 год | `src/updater.js` |
| RPC-вузли мереж (publicnode, drpc, 1rpc, офіційні) | баланси й транзакції | лише коли гаманець розблоковано й відкрито | `src/wallet-evm-core.js`, `src/wallet-solana.js` |
| `api.coingecko.com` | ціни токенів | лише для гаманця | `src/prices.js` |
| `api.pwnedpasswords.com/range/` | перевірка пароля за префіксом SHA-1 (k-анонімність) | лише за явною дією користувача | `src/vault.js` |
| `sourcify.dev` | розшифровка викликів контракту | лише при підписанні | `src/wallet-simulate.js` |

Chromium сам може звертатися до `wpad` (автовизначення проксі). Усе інше — запити сторінок, які відкриває користувач.

_Перевірено 2026-10-26 (`npm run net-audit`, чистий профіль): на старті — лише списки загроз і правила реклами; під час набору тексту з помилками (спелчек) запитів немає, словники не завантажуються; у спокої — нуль запитів, крім `wpad`. Упакована збірка (`npm run net-audit:packaged`, опитування TCP-з'єднань ззовні): через ≈16–22 с після старту — з'єднання зі списками загроз (gitlab.io), правилами реклами (GitHub raw) і перевіркою оновлень (GitHub); за наступні 90 с спокою нових з'єднань немає. Прилад: `src/net-audit.js` (сесії Chromium + з'єднання Node) і DNS з net-log; вмикається лише в неупакованій збірці._

## Збірка

`electron-builder` (NSIS + portable), `build/installer.nsh` реєструє браузер у Windows. Файл `build/installer.nsh` **підхоплюється автоматично** будь-якою збіркою із цієї теки (навіть без `nsis.include`). Fuses Electron задаються в `package.json → build.electronFuses`.
